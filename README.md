# Aura Finance

**Finance Impact Copilot | HackUTD**

Aura Finance connects economic events to personal financial circumstances through
a rule-based impact dashboard and optional AI explanations.

> Economic news tells you what happened. Aura Finance helps you understand what
> it could mean for your money.

**Theme:** Artificial Intelligence + Financial Literacy + Economic Intelligence
+ Personalized Decision Support.

**Status:** Local hackathon MVP implemented. This is an educational prototype,
not a commercially deployed financial service.

## The problem

People hear about inflation, interest rates, jobs reports, and housing trends,
but often struggle to understand their relevance to their income, business,
investments, or property. Aura Finance makes those relationships understandable
without claiming to predict anyone's financial future.

Target users include students, retail investors, small business owners, and
homeowners exploring economic scenarios.

## Four features, one demo

| Feature | Implemented behavior |
|---|---|
| Demo financial profile | Occupation, income range, and business, investment, and property exposure; versioned API also stores stock tickers and property counts; no account required |
| Economic event selector | Five hypothetical events: inflation up, interest rate increase, strong jobs report, housing slowdown, and Federal Reserve rate hike |
| Impact engine | Ten deterministic business rules produce four impact cards with attention labels, explanations, and considerations |
| AI explanation | Follow-up questions grounded in a saved analysis through an OpenAI-compatible API |

Profiles, holdings, recommendations, analysis snapshots, and successful chat
exchanges are stored in SQLite. Changing the profile or event in the React form
clears the old dashboard so results cannot be mistaken for a new scenario.
API profile updates do not rewrite previous analysis snapshots.

**Without an AI key:** the entire profile-to-dashboard workflow still works.
The app explicitly labels AI as unconfigured and disables AI questions. It never
substitutes a fake AI response.

**With an AI key:** the backend sends the saved event, profile context, business
rules, assumptions, and question to the configured provider. Names and database
metadata, stock tickers, and property counts are omitted. Provider errors are
shown explicitly. Suggested dashboard recommendations are generated by business
rules, not AI; AI answers are labeled separately.

## Quick start

Prerequisites: **Python 3.11+** and **Node.js 22+** with npm.
Commands below use a macOS/Linux shell.

```bash
git clone https://github.com/phuongcodes2025-sys/aura-finance.git
cd aura-finance
```

### 1. Start the backend

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:app --reload --env-file .env --host 127.0.0.1 --port 8000
```

Leave `OPENAI_API_KEY` empty to try the rule-based demo. For AI explanations,
edit `backend/.env` and restart the backend:

```dotenv
DATABASE_PATH=./aura.sqlite3
OPENAI_API_KEY=your-provider-key
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-4o-mini
```

For another OpenAI-compatible provider, use its base URL and supported model.
The integration uses `/chat/completions` with `max_tokens`; your provider must
support that interface. A configured key does not guarantee provider access,
quota, or model availability.

### 2. Start the frontend in a second terminal

From the repository root:

```bash
cd frontend
npm ci
npm run dev
```

Open **http://127.0.0.1:5173**.
API documentation is at **http://127.0.0.1:8000/docs**.

Vite proxies `/api` to the backend on port 8000, keeping requests same-origin.
There is no need to configure browser CORS or expose AI credentials to React.

### Production-build preview

With the backend still running:

```bash
cd frontend
npm run build
npm run preview
```

Open **http://127.0.0.1:4173**. The preview server also proxies `/api` locally.
This is a build preview, not a production deployment configuration.

## A three-minute judge demo

| Time | Story and action |
|---|---|
| 0:00-0:30 | Explain the gap: "I hear economic news, but what does it mean for me?" |
| 0:30-1:00 | Click **Use Dallas business owner demo**; the profile includes investment and rental-property exposure and selects a rate increase |
| 1:00-1:45 | Click **Analyze impact**; walk through income, business, investments, and real estate |
| 1:45-2:30 | With AI configured, ask "Why should my business pay attention to higher interest rates?" |
| 2:30-3:00 | Open the assumptions; explain that rules determine labels, AI explains them, and no live data or guaranteed predictions are involved |

The core click-through requires only loading the demo profile and clicking
Analyze. The React form captures broad investment exposure, not specific holdings.
The versioned API can store holdings such as NVDA, but rules still use only broad
exposure flags; do not imply ticker-level portfolio analysis or rental cash-flow
calculations.

## How the rules work

`backend/app/impact.py` contains five curated event descriptions and exactly ten
rules. A rule can cover multiple related events. Each supported event matches
exactly one rule per active financial area. The Federal Reserve rate-hike scenario
uses the existing interest-rate rules, including conditional mortgage exposure.

- Income always receives an analysis.
- Unselected business, investment, or property exposure is **Not applicable**.
- Active areas receive **Low**, **Moderate**, or **High attention** labels.
- Every active card includes its rule ID, reasoning, and suggested considerations.
- Income range and occupation provide context, not dollar calculations or score adjustments.

Labels express qualitative educational attention, not loss probabilities or
personalized risk measurements. For example, a rate increase does not
automatically change an existing fixed-rate mortgage payment. The rules explicitly
distinguish that from new or variable-rate financing.

The AI does not perform financial calculations or choose the rule-based labels.
Its prompt instructs it to preserve the supplied labels, explain uncertainty,
avoid specific trading recommendations, and stay within the scenario.
AI outputs still require verification.

```mermaid

    UI[React + Vite + Tailwind CSS] -->|Same-origin /api proxy| API[FastAPI]
    API --> DB[(SQLite profiles, events, analysis snapshots)]
    API --> Rules[10 deterministic impact rules]
    Rules --> Dashboard[Four impact cards]
    DB --> Context[Saved analysis context]
    Context --> AI[Optional OpenAI-compatible explanation]

    Dashboard --> UI
```

### Storage

Persistence uses Python's standard-library SQLite driver, not SQLAlchemy.

| Table | Stored information |
|---|---|
| `users` | Demo name, occupation, income range, exposure flags, timestamp |
| `economic_events` | Five seeded event IDs, titles, categories, descriptions |
| `analysis_results` | Profile/event references, timestamp, complete JSON snapshot |
| `stocks` | User reference and unique stock tickers |
| `properties` | User reference, property type, positive property count |
| `recommendations` | Analysis reference, ordered rule-generated suggestions, source, timestamp |
| `chat_messages` | User/analysis references, role, message, timestamp |

Tables are created on startup and events are seeded idempotently. Foreign keys
are enabled. JSON snapshots preserve the exact profile, event, rules, and
assumptions used for later AI questions, including the holdings at analysis time.
Existing databases gain the new tables without removing existing records.
Older saved analyses are supplemented with rule-generated recommendations and
summaries derived from their saved impact cards, not recalculated rules.

Deleting a profile also deletes its holdings, analyses, recommendations, and
chat history in one transaction; it leaves economic events and other profiles
intact. Profile updates preserve historical analyses.

The database is created at `DATABASE_PATH`, relative to the backend working
directory by default. Database files and environment secrets are gitignored.

## API

The existing `/api` routes use camelCase and remain compatible with the React
app. The new `/api/v1` routes use snake_case. Invalid inputs return `422`;
unknown profiles, events, or analyses return `404`.

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/health` | Backend readiness and whether AI credentials are configured |
| GET | `/api/events` | List the five demo scenarios |
| GET | `/api/events/{event_id}` | Retrieve one scenario |
| POST | `/api/profile` | Save a demo profile; returns `201` |
| GET | `/api/profile/{user_id}` | Retrieve a saved profile; unknown IDs return `404`, non-positive or invalid IDs return `422` |
| PATCH | `/api/profile/{user_id}` | Update supplied profile fields |
| DELETE | `/api/profile/{user_id}` | Delete a profile and its dependent records |
| GET | `/api/profile/{user_id}/analyses` | List saved analyses, newest first |
| POST | `/api/analyze` | Apply rules and save an analysis; returns `201` |
| GET | `/api/analysis/{id}` | Retrieve the saved analysis snapshot |
| GET | `/api/dashboard/{id}` | Retrieve profile, event, analysis, and recommendations together |
| POST | `/api/chat` | Explain a question using an existing analysis |
| GET | `/api/chat/{id}` | Retrieve successful chat exchanges for an analysis, oldest first |

Create a profile:

```json
{
  "name": "Dallas demo",
  "occupation": "Small business owner",
  "incomeRange": "60k-100k",
  "businessOwner": true,
  "investor": true,
  "propertyOwner": true
}
```

Supported income ranges: `under-30k`, `30k-60k`, `60k-100k`, and `over-100k`.
`name` is optional; the remaining profile fields are required.

Analyze using the returned profile ID:

```json
{ "userId": 1, "eventId": 2 }
```

Ask AI using the returned analysis ID:

```json
{
  "analysisId": 1,
  "question": "Why should my business pay attention to higher rates?"
}
```

Chat returns `{ "answer": "...", "source": "ai" }`. A missing AI key returns `503`;
provider connection, rejection, or malformed-output failures return `502`;
provider timeouts return `504`. No failure is presented as a successful AI answer.

Both API versions store the user message and AI answer together only after a
successful provider response. Failed requests leave chat history unchanged.
Each question is grounded in the saved analysis; prior chat messages are available
through history endpoints but are not currently sent to the provider.

### Versioned workflow: `/api/v1`

| Method | Path (after `/api/v1`) | Purpose |
|---|---|---|
| POST | `/profile` | Save profile and holdings; returns `201` with `id` and a message |
| GET | `/profile/{user_id}` | Retrieve profile, holdings, and exposure flags |
| PATCH | `/profile/{user_id}` | Update only supplied fields; returns updated profile |
| PUT | `/profile/{user_id}` | Replace editable profile fields using the create request shape |
| DELETE | `/profile/{user_id}` | Delete profile and dependent data |
| GET | `/profile/{user_id}/analyses` | Retrieve analysis IDs, saved event names, and timestamps, newest first |
| GET | `/events` | List existing event IDs, names, categories, and summaries |
| GET | `/events/{event_id}` | Retrieve one event |
| POST | `/analyze` | Save analysis, summary, and at least three rule-generated recommendations |
| GET | `/analyze/{analysis_id}` | Retrieve the saved result |
| GET | `/dashboard/{analysis_id}` | Retrieve the saved profile, event, analysis, and recommendations |
| POST | `/chat` | Return an AI explanation and save the successful exchange |
| GET | `/chat/{analysis_id}` | Retrieve messages in insertion order |

All path IDs must be positive integers. Use **PATCH** for partial updates such as
`{"income_range": "100k-125k"}`; **PUT** requires name, occupation, and income range
and resets omitted business/holdings fields to their create defaults.
Empty PATCH requests, explicit null fields, duplicate tickers, and non-positive
property counts return `422`. Tickers are normalized to uppercase.

Create Sarah with `POST /api/v1/profile`:

```json
{
  "name": "Sarah",
  "occupation": "Nail Salon Owner",
  "income_range": "75k-100k",
  "business_owner": true,
  "stocks": ["NVDA", "AAPL"],
  "properties": [
    {"property_type": "Rental Property", "property_count": 2}
  ]
}
```

Version 1 also accepts the four original income ranges and `100k-125k`.
Stock/property lists determine the corresponding exposure flags. Omitted lists
are empty; setting a list to `[]` in PATCH removes those holdings and clears the
flag. Legacy exposure-only profiles remain supported. Disabling a legacy exposure
flag while holdings still exist returns `409`; remove those holdings through
version 1 first.

Run `POST /api/v1/analyze` with the returned user ID and the existing rate-increase
event ID **2**:

```json
{"user_id": 1, "event_id": 2}
```

The response includes `analysis_id`, `created_at`, `income`, `business`,
`investments`, `real_estate`, `overall_summary`, `recommendations`,
`recommendation_source: "rules"`, and `assumptions`. Each area has a risk attention
label, summary, and explanation. Labels are `Low`, `Moderate`, `High`, or
`Not applicable`. The rate scenario retains **Moderate** real-estate attention
because existing fixed-rate payments do not automatically increase.

Use the returned analysis ID with `GET /api/v1/dashboard/{analysis_id}`.
It returns the profile and holdings **as they were when the analysis ran**, not
the latest edited profile.

With AI configured, send `POST /api/v1/chat`:

```json
{
  "user_id": 1,
  "analysis_id": 1,
  "message": "How could higher interest rates affect my nail salon?"
}
```

Replace both IDs with the returned values. Chat returns
`{"response": "...", "source": "ai"}` and uses the same explicit provider error
statuses as the legacy route. A mismatched profile/analysis returns `404` without
calling AI. This consistency check is not authentication or authorization.

### Preload the demo

From `backend`, with the virtual environment active:

```bash
python -m app.seed
```

This creates a **new** synthetic Sarah profile, NVDA/AAPL holdings, two rentals,
and a saved rate-increase analysis each time it runs. It prints the profile ID,
analysis ID, and dashboard path. Events remain seeded idempotently.
For a custom database, supply the same path used by the server:

```bash
python -m app.seed --database ./aura.sqlite3
```

The seed command reads `DATABASE_PATH` from the shell environment, not `.env`
automatically. Inspect the printed dashboard path in `/docs`; the current React
demo button still creates its own broad-exposure profile.

## Scope boundaries and responsible use

Excluded from this weekend MVP: authentication, real stock prices, portfolio
uploads, Bloomberg integration, real-time news, RAG, watchlists, and multi-agent
systems.

This local app has no authentication or record-level access controls. Anyone
with access to its API can read, edit, or delete profiles and their saved data,
retrieve chat history, and invoke configured AI.
**Do not expose it publicly or use it with real financial records.** The servers
bind to localhost by default. Commercial deployment would require authentication,
authorization, rate limits, data protection, and further financial validation.

Use synthetic profiles. Never commit API keys, `.env` files, or personal
financial records. When AI is enabled, profile context and questions are sent to
the chosen provider; do not put private information in either.

Aura Finance is educational information, not licensed financial advice, a trading
service, or a prediction engine. Economic relationships are conditional, and AI
can be wrong.
